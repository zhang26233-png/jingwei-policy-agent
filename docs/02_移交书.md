## 0. 三十秒版本

一个单端口 Node 应用：前端 React 19 + Vite，后端 Node 原生 `http`，同端口 8787 同时提供页面和 API。

它抓 7 个中央部委官网 + 8 个地方政府门户的政策文件，做结构化抽取，然后算四类东西：政策优先级、传导机制链、政策间关系、省级影响；外加一个独立的**央地传导**模块，比对中央发文日与地方跟进日的时间差。

**所有数值结论来自可复算的规则，模型不参与数值判断。** 这是整个项目的立足点，改代码时不要破坏它。

## 1. 三条红线

违反任何一条，这个项目就变成了它自己批评的那种"套壳大模型"。

### 红线一：抓不到就留空，不许编

`server/locals.mjs` 里 8 个省份源，只有 6 个能过可用性门槛。剩下 2 个（山西、江苏）必须显示"未纳入"并写明原因，**不允许**用邻近省份推断填补，**不允许**改阈值让它们"通过"。

同理，中央语料抓取失败时不允许回落到手写样例而不标注。

### 红线二：数值结论必须可复算

任何在页面上出现的分数、排名、天数，都必须能由 `src/lib/` 下的纯函数从原始数据算出，且能定位到具体规则。**不要把数值判断交给模型。**

模型（如果接入）的职责边界：把已算好的规则结果写成可读段落。它读不到原始打分的中间过程，也不该改分。

### 红线三：边界要写在页面上，不是写在文档里

每一条限制（覆盖率、观测窗、样本量、不能用什么口径）都要出现在用户能看到的界面里。文档里写了但页面上没写，等于没写——评审不会读文档。

具体位置：`TransferView.tsx` 的「能回答什么、不能回答什么」区块与「口径与边界」清单；`ImpactView.tsx` 的 `map-scope` 说明块。

## 2. 跑起来

环境要求：**Node.js 20+**（本机验证 v22.22.2 / npm 10.9.7）。无数据库、无外部服务依赖。

```bash
cd macro-policy-agent
npm install
npm start            # = npm run build && node server/index.mjs
# 打开 http://127.0.0.1:8787/
```

开发模式（前端热更新）：

```bash
npm run server       # 终端 1：API，端口 8787
npm run dev          # 终端 2：Vite，端口 5173（已配 proxy 到 8787）
```

### 三个必跑的自检

```bash
npm run lint         # oxlint，应为 0 error
npx tsc -b           # 类型检查，应无输出
npm run build        # 产物在 dist/
```

改完代码后**必须**同步一份静态产物，否则线上/单端口模式会用到旧页面：

```bash
rm -rf webdist && cp -r dist webdist
```

> `webdist/` 是入库的兜底产物。`dist/` 在 `.gitignore` 里，`webdist/` 不在。
> `server/index.mjs` 优先找 `dist/`，缺失时回落 `webdist/`。这是为了保证别人 clone 下来即使不 build 也能看到页面。

## 3. 架构

```
浏览器
  │
  ├─ 静态页面 ── dist/ 或 webdist/（Vite 产物）
  │
  └─ /api/* ──── server/index.mjs（Node 原生 http，单端口 8787）
                   │
                   ├─ sources.mjs    中央来源定义 + 列表解析
                   ├─ net.mjs        请求、限速、重试、编码（含 GBK/GB2312 解码）
                   ├─ extract.mjs    正文抽取 + 结构化字段 + 文种判定
                   ├─ pdf.mjs        PDF 附件解析（正文并入）
                   ├─ audit.mjs      抽取覆盖率与缺失归因（仅供 scripts/audit-quality.mjs 调用，无 HTTP 入口）
                   ├─ locals.mjs     地方政府门户采集（8 源）
                   └─ store.mjs      落盘 data/policies.json
```

### 数据流

| 触发 | 路径 | 落盘 |
|---|---|---|
| 页面「自动扫描」→ `POST /api/collect` | sources → net → extract → store | `data/policies.json` |
| `node scripts/collect-locals.mjs` | locals.mjs → 8 个地方源 | `data/locals.json` |
| 页面读取 | `GET /api/corpus`（中央）/ `GET /api/locals`（地方） | — |
| 前端计算 | `src/lib/*.ts` 纯函数，在浏览器里跑 | 无 |

**关键设计：所有统计与判定在前端做，后端只负责抓取和存储。** 好处是数据一改，所有推导自动重算；坏处是首屏要把整个语料传下去（当前 `data/locals.json` 3.4MB，走 gzip 后约 500KB）。

### 接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/progress` | 采集进度（SSE 轮询用） |
| GET | `/api/policy?id=` | 单条政策 |
| GET | `/api/corpus` | 中央语料全量 |
| GET | `/api/locals` | 地方语料；未采集时返回 `{ready:false}` |
| POST | `/api/collect` | 触发中央采集 |
| POST | `/api/attachments/backfill` | 补抓 PDF 附件正文 |

## 5. 央地传导模块详解（本轮新增，最容易改错）

### 5.1 判定状态机

一格（省份 × 主题）只有六种状态，**不要新增第七种而不更新图例和文案**：

| 状态 | 含义 | 计入时滞统计 |
|---|---|---|
| `respond` | 标题命中且地方文件晚于中央发文 | ✅ 是 |
| `pre` | 标题命中但地方文件早于中央 | ❌ 否（方向相反） |
| `likely` | 标题没命中，但正文里同主题出现 ≥5 次且晚于中央 | ❌ 否（待核） |
| `none` | 标题与正文都没有 | ❌ 否 |
| `outside` | 中央发文日落在该地栏目观测窗之外 | ❌ 否（无法判断） |
| `uncovered` | 该地未过可用性门槛 | ❌ 否 |

**`none` 和 `outside` 绝不能合并。** 合并就等于"用栏目边界当政策事实"，这是本项目早期最大的口径错误。

**`pre` 不能并进时滞统计。** 否则中位数被系统性压短。

### 5.2 可用性闸门

```ts
const GATE = { minRecentDocs: 6, minLatest: '2026-10-20' };
```

- `minRecentDocs`：近 90 天政策文件数下限。**不要改成"总条数"**——黑龙江总条数 35 但近 90 天只有 4 份，用总条数会把它判成可用，然后大量假阴性。
- `minLatest`：栏目最后更新日期下限。**这是硬编码日期**，不是相对时间。见缺陷 D3。

### 5.3 事务性文件过滤

```ts
const DOC_LIKE = /(通知|意见|方案|办法|措施|规划|细则|实施|规定|指引|清单|计划|决定)/;
const EXCLUDE_DOC = /(培训|征集|课题|名录|名单|解聘|聘任|招聘|笔试|面试|遴选|公示|资质|年检|考核|评比|竞赛|表彰|获奖|采购|招标|中标|预算公开|决算|职称|考试|批复|复函)/;
```

`EXCLUDE_DOC` 里的每一个词都是拿真实误判换来的：

- "人工智能领域颠覆性技术方向储备**课题征集**" → 曾被算成 +0 天响应
- "文物保护工程**资质**单位**培训班**" → 曾被算成文化遗产 +14 天

**加词容易，减词要先核对原始数据。** 减一个词可能让响应组数从 7 涨到 11，而且涨出来的多半是假的。

### 5.4 主题锚点

18 个锚点在 `THEMES` 数组里，每项含 `centralTitle`（正则）、`centralDate`（兜底日期）、`keys`（地方匹配正则）、`why`（为什么选它）。

**别改回"专项工具"路线。** 早先只用 8 个专项工具（购房贴息、农业保险、清欠回款…），在 617 份地方文件里几乎全零命中——因为地方落实这类专项多走**部门文件**，省级门户的"政策文件"栏目收不全。改成领域锚点后才有观察量。

### 5.5 时滞排行（本轮新增）

`buildLagRanking(result)` 把所有 `respond` 格子拉平按天数排序，返回 `items` / `median` / `max` / `bands`。

网页用 CSS grid 渲染（`transfer.css` 的 `.trf-rank-*`），导出用 canvas 重绘（`exportImage.ts` 的 `drawRankChart`）。

**两处实现，一套数据。** 改配色或分档规则时两边都要改，否则会出现"屏幕上是绿的、导出图是黄的"。

两边的分档必须一致：

| 档 | 天数 | 网页色 | 导出色 |
|---|---|---|---|
| fast | ≤30 | `--green` #2ee6b2 | #12967f |
| mid | 31—60 | `--amber` #ffc247 | #cf9a1f |
| slow | >60 | `--rust` #ff8f6b | #d2603c |

**刻度上限两边都要取整到 30 的倍数。** 早先导出用的是 `max × 1.08`，同一根条在屏幕上和在 PNG 里读出的天数不一样，已修。

## 6. 数据契约

### `data/locals.json`

```jsonc
{
  "ready": true,
  "at": "2026-11-07T05:44:36.626Z",   // 采集时间，导出图文件名用它
  "since": "2026-05-01",
  "coverage": { "crawled": 8, "attempted": 8, "totalProvinces": 31 },
  "provinces": [
    {
      "id": "beijing",
      "name": "北京市",
      "short": "北京",
      "level": "省级（直辖市）",        // ⚠️ 判断省级/市级必须用 startsWith
      "kind": "市政府及部门文件",        // 栏目收录范围，写进口径说明
      "list": "https://...",
      "count": 398,
      "recentDocs": 215,                // 近 90 天政策文件数，可用性闸门看这个
      "earliest": "2026-05-06",          // 观测窗下界
      "latest": "2026-11-06",            // 观测窗上界
      "errors": [],
      "items": [
        { "title": "...", "date": "2026-11-06", "url": "...", "text": "正文前 3000 字" }
      ]
    }
  ]
}
```

**注意 `level` 字段**：广州的值是 `"市级（副省级省会）"`，字符串里包含"省级"三个字。早期用 `includes('省级')` 判断导致广州被算成省级，覆盖率分母从 31 变成错的数。**必须用 `startsWith('省级')`。**

### `data/policies.json`

```jsonc
{
  "version": 3,
  "updatedAt": "...",
  "runs": [...],
  "sources": [...],
  "policies": [
    {
      "id": "...", "title": "...", "shortTitle": "...",
      "date": "2026-11-04", "issuer": "...", "sourceLevel": "...",
      "docType": "政策文件",          // 政策文件 / 工作动态 / 数据发布 / 发布实录
      "bodyLength": 4821,
      "origin": "auto"                // auto = 采集；其他 = 人工校订
    }
  ]
}
```

当前 98 条：政策文件 63、工作动态 17、数据发布 16、发布实录 2。

**`docType` 判定规则在 `server/extract.mjs` 的 `DOC_RULES`，顺序敏感。** 规则是按优先级依次匹配的，把一条规则往前挪可能改变几十条的归类。已知踩坑：某条标题含「出席」「论坛」「开幕式」的稿件必须判为工作动态，且这条规则要放在政策文件规则**之后**。

## 8. 已知缺陷（按严重度排序）

### D1 · 地方语料是静态快照，不会自动更新 【高】

`data/locals.json` 落盘于 2026-11-07，线上服务不会定时重跑采集。随着时间推移，"近 90 天"的统计会失真，`GATE.minLatest = '2026-10-20'` 这个硬编码日期也会逐渐把所有省份判成"停更"。

**后果**：三周后打开页面，6 个可用省份可能全部变成"未纳入"，央地传导页会空掉。

**建议解法**：把 `minLatest` 改成相对于 `payload.at` 的偏移（如 `at - 18天`），并给 `collect-locals.mjs` 加定时执行或在服务启动时按需重跑（注意采集耗时 8—12 分钟，不能卡住首屏）。

### D2 · 中央语料与地方语料时间不同步 【中】

中央 98 条截至 2026-11-04，地方 617 份截至 2026-11-06。页面同时展示两者时没有提示这一差异。若中央重新采集而地方没重跑，会出现"地方文件比中央语料还新"的错觉。

**建议解法**：在央地传导页头部显示两个数据时间戳。

### D3 · 7 组样本量过小 【中，且不可通过工程手段解决】

中位时滞 16 天是从 7 个观测算出来的，置信区间很宽。任何加强"16 天"这个数字的表述都是过度解读。

**唯一解法是扩样本**，但已实测 31 个省级门户只有 5 个能抓（见 `03_...` 与 `probe-provinces.mjs`）。要么接受，要么改数据源（购买政策数据库 / 接入商业 API）。

### D4 · 22 处疑似漏抽未人工核对 【中】

抽取环节标记了 22 处「疑似漏抽」：字段在原文中存在线索，但未抽到。该数字未逐条核验，可能虚高，也可能有遗漏。

**这是目前最该做的人工工作**：`node scripts/audit-quality.mjs --gaps` 列出清单，逐条比对原文，30 条抽检约需 1 小时。

### D5 · 零自动化测试 【中】

整个项目没有单元测试，只有 `lint` + `tsc` + `build` 三道静态关卡。`src/lib/` 下全是纯函数，是最容易补测试的地方，也最值得补——尤其是 `transfer.ts` 的 `buildTransfer` 与 `buildLagRanking`，它们的输出直接变成页面结论。

**建议**：先用 `data/locals.json` 的真实切片做 fixture，断言"6 个可用、7 组跟进、中位 16 天"。这条断言能挡住未来 80% 的口径回归。

### D6 · 导出图与网页是两套渲染 【低，但会漂移】

`exportImage.ts` 用 canvas 重绘，与 `transfer.css` 的 CSS 实现并行。改了配色/分档/刻度规则必须同步两处。已在移交书里写明，但没有机制强制。

**建议**：把分档规则（`TONE` 与 `bandOf`）抽到一个共享常量文件，两边都引用。

### D7 · 主题锚点泛化风险 【低】

`房地产` 的 `keys` 是 `/房地产|住房信贷|住房市场|保障房|城中村/`，覆盖面很宽。一份泛泛提及"房地产"的文件可能被算成对该主题的响应。

同理 `政务服务` 的 `一件事` 可能命中无关文件。

**建议**：对 `respond` 结果做一次人工抽检（当前 7 组，10 分钟能看完）。

### D8 · 江苏源第 2 页 404 【低】

`jiangsu` 只拿到 1 份文件且 `errors: ["第 2 页：HTTP 404"]`，已因不可用被排除。若要修复需重查分页 URL 规则。

### D9 · `data/locals.json` 3.4MB 入库 【低】

每次采集都会产生巨大的 diff。可接受（保证 clone 即可用），但要知道仓库会越来越大。

## 9. 关键决策记录（不要轻易推翻）

| 决策 | 理由 |
|---|---|
| 统计在前端算，不在后端 | 数据一改全部重算，不需要重启服务 |
| 主题级配对而非文件级 | 央地文件之间没有官方对应编号，做不了文件级 |
| 保留 `webdist/` 入库 | 保证 clone 后不 build 也能看到页面 |
| 央地传导独立成页，不并入省级影响 | 两套口径混在一起必然被误读，宁可分开放 |
| 抓不到就留空 | 编造数据会让整个项目的"可核查"主张失效 |
| 用 canvas 手绘导出图 | SVG 序列化后中文字体常丢失，canvas 更稳 |
| 导出图用白底 | 图的去处是 Word / PPT / 打印，不是深色屏幕 |

## 10. 术语表

| 术语 | 含义 |
|---|---|
| PCI | 政策一致性指数（Policy Coherence Index），三个维度：横向、时序、目标—工具 |
| PEI | 政策可执行性指数（Policy Executability Index），五问：目标可测 / 责任可归 / 资源有保障 / 时限明确 / 可考核 |
| 观测窗 | 某个地方栏目能回溯到的日期范围。窗外的不做判断 |
| 可用性闸门 | 近 90 天 ≥6 份文件 且 栏目更新晚于 10-20 |
| 响应 / 跟进 | 地方在中央发文之后发布了同主题标题命中的政策文件 |
| 先行 | 地方文件早于中央发文，说明中央可能在追认地方做法 |
| 疑似承接 | 标题没命中但正文反复提及，标 `likely`，不计入统计 |
| 主题锚点 | 一项中央文件 + 一组地方匹配关键词 |
| 事务性文件 | 培训班、课题征集、名录公示等非政策工具文件 |
| 便利样本 | 能抓到什么就用什么，不是随机抽样 |
