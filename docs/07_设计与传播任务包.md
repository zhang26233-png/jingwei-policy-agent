## 1. 三分钟理解这个项目

**它是什么**：一个中国宏观政策证据分析工作台。把国务院、发改委、财政部、人民银行等 7 个官方来源的政策原文抓下来，抽出「工具—渠道—目标」，算出优先级，再回答一个具体问题：**中央发了一个政策，地方有没有跟着做、隔了几天做。**

**它在回答谁的什么问题**：老师问的原话是——

> 「中央政府做了一个政策，地方是否做了，何时做的；中央—地方之间的一个时间差，是不是全国层面有差异」

**它给出的答案**（这三个数字是全篇的骨架，必须记准）：

| 结论 | 数字 |
|---|---|
| 典型时滞 | 中位 **16 天**，最快 **+6 天**，最慢 **+77 天** |
| 能确认的跟进 | 107 个可判组合里只有 **7 组** |
| 跨地区差异的真相 | 先差在**看得见多少**，不差在动得多快 |

第三个结论是这个项目区别于普通课程作业的地方。它承认了自己的观测边界，反而更可信。**PPT 和视频里这条必须保留，不许为了好看改成「全国差异显著」。**

## 3. 任务 A：汇报 PPT

### 3.1 基本要求

| 项 | 要求 |
|---|---|
| 页数 | **14 页**（含封面与结尾），不要超过 16 页 |
| 比例 | 16:9，1920×1080 |
| 场合 | 校内评审 / 向指导老师汇报，10—12 分钟讲完 |
| 语言 | 全中文。专业术语第一次出现时给一句解释 |
| 风格 | 沿用平台的深色情报终端风（见第 6 节），**不要做成通用商务蓝白模板** |

### 3.2 逐页大纲（照这个写，不要自己重排顺序）

**P1 封面**
- 主标题：经纬纵横
- 副标题：中央政策到地方落地的时滞观测
- 一行小字：中国宏观经济政策证据分析工作台
- 底部：汇报人 / 日期 / 「2026 青振京郊专项赛」

**P2 老师的问题**
- 标题：一个问题，三个层次
- 内容：把老师原话拆成三问——①地方做了没有 ②隔了多久 ③全国有没有差异
- 视觉：三行，每行一个问题，右侧标注「本项目怎么答」
- 这一页的目的是让评审看到「我们听懂了问题」

**P3 一句话答案**
- 标题：答案
- 主视觉：三个大数字并排 —— `16 天`（中位时滞）/ `7 组`（可确认）/ `6 个`（可观测单元）
- 下方一句：**典型两周，尾部两个半月；但能确认的样本只有 7 组，所以只做案例比较，不做全国推断**
- 这一页是全篇最重要的一页。数字要大，句子要短

**P4 平台全景**
- 标题：一个能用的工作台，不是一张图
- 内容：8 个页面的名称与一句话功能，用 `docs/screenshots/` 里的六张截图拼成截图墙（不必 8 张全放）
- 六个可放的：政策扫描、政策库、省级影响、政策协同、央地传导、研究报告

**P5 数据从哪来**
- 标题：数据全部来自官方公开页面
- 左：中央侧 —— 7 个来源 / 98 份 / 2026-07-31 至 11-04
- 右：地方侧 —— 31 个目标 / 8 个接入 / 6 个可用 / 617 份
- 底部一行：**不登录、不上报、不绕过验证码；抓不到的就写抓不到**

**P6 怎么算「跟进了」**
- 标题：判定规则是可复核的，不是拍脑袋
- 内容：一张四状态说明表
  - 确认跟进（respond）：地方文件日期晚于中央锚点，且正文命中主题关键词
  - 地方先行（pre）：地方同类文件早于中央锚点
  - 可能相关（likely）：提到但不足以判定
  - 未命中（none）：可观察但零命中
- 强调：每条判定都能点回原文

**P7 发现一 · 时滞**
- 标题：典型的等两周，最长等了两个半月
- 主视觉：时滞排行条形图（用 `report-sample.html` 里的图 1，或按同数据重绘）
- 7 组按天数排序，中位线 16 天，30/60 天分档着色
- 一句注解：**5 组落在 30 天内；唯一拖到 77 天的是河北的电力事项**

**P8 发现二 · 覆盖率**
- 标题：107 个格子里，能确认的只有 7 个
- 主视觉：18×6 响应矩阵（报告图 2）
- 一句注解：**零命中不等于没落实——更可能是「落实不走省级门户的政策文件栏目」。这是观测问题，不是执行问题**

**P9 发现三 · 差异的真相（最重要）**
- 标题：跨地区比的首先是「看得见多少」
- 主视觉：散点图（报告图 4）——横轴近 90 天公开文件数（对数），纵轴跟进组数
- 一句注解：**北京公开 215 份、观察到 5 组；广东 10 份、广州 9 份、陕西 8 份，各 0 组**
- 底部小字：仅 6 个观测点，只作描述，不做回归与显著性判断
- ⚠️ 这一页不要美化成一个干净的上升趋势线。图上不画拟合线

**P10 全国层面能说到什么程度**
- 标题：诚实的边界
- 主视觉：漏斗图 31 → 8 → 6（报告图 5）
- 三件不做的事（写成三行，醒目）：
  1. 不给未接通省份插补数据
  2. 不用 7 组样本做统计检验
  3. 不用「东快西慢」包装样本缺口
- 这一页是防答辩的。老师很可能会问「31 个省你怎么都有」——这页就是答案

**P11 研究报告**
- 标题：已经形成一份完整报告
- 内容：报告封面截图 + 目录结构（核心结论 / 数据方法 / 三个发现 / 边界 / 明细 / 风险提示 / 口径附录）
- 标注：8 页 A4，5 图 5 表，可打印可直接分发
- 右下角放线上访问地址（见第 6 节）

**P12 与常见做法的区别**
- 标题：做对了什么
- 三列对比（本项目 vs 常见课程作业）
  - 有原文回溯 vs 只有结论
  - 声明观测边界 vs 假装全国覆盖
  - 规则可复算（`npm run verify` 10 条断言）vs 数字不可验
- ⚠️ 措辞要克制，不要贬低其他项目，用「我们选择」而非「他们错误」

**P13 局限与下一步**
- 标题：还差什么
- 三条（照实写，不要美化）：
  1. 可用性判据里有硬编码日期，快照过期后可用省份会整批掉落 → 改成相对偏移（P0）
  2. 只接入 8 个地方门户，扩源需要为每省写适配器或购买政策数据库
  3. 22 处疑似漏抽未人工核，7 组时滞判定未人工复核
- 一句：**这些是已知的，不是被发现的**

**P14 结尾**
- 一句话：把「政策有没有落地」从判断题变成可复核的观测题
- 附加：访问地址 + 一句话邀请试用

### 3.3 PPT 的硬性要求

1. **每页只讲一件事。** 一页塞两个观点就拆开。
2. **数字必须来自第 2 节。** 不许四舍五入到「约 20 天」这种模糊说法。
3. **图表不要重绘成风格化的假图。** 直接用报告里的 SVG（矢量，能无损放大）或截图。重绘时数据必须一致。
4. **不要在图上加拟合线、趋势箭头、光效。** 现在的图已经足够，加装饰会削弱可信度。
5. **中文字体**：标题用思源宋体 / 思源黑体 SemiBold，正文思源黑体 Regular，数字用等宽字体（IBM Plex Mono 或 JetBrains Mono）。不要用「微软雅黑 + 艺术字」。
6. **每页右下角标页码与项目名小字**，方便评审记笔记。

## 4. 任务 B：演示视频

### 4.1 两个版本

| 版本 | 时长 | 用途 |
|---|---|---|
| 短版 | **90 秒** | 答辩前的暖场 / 展台循环播放 |
| 长版 | **3 分钟** | 线上提交 / 嵌入汇报 |

先做短版，确认节奏对了再做长版。

### 4.2 90 秒分镜脚本（照这个结构）

| # | 时间 | 画面 | 旁白 |
|---|---|---|---|
| 1 | 0—8s | 深色底，标题浮现「经纬纵横」+ 一行副标题 | 中央发了一个政策，地方到底跟不跟？ |
| 2 | 8—22s | 首页截图，鼠标点「启动扫描」，进度条推进，7 个来源逐个亮起 | 系统自己去找——七个官方来源，近三个月的政策原文，不用你写提示词 |
| 3 | 22—40s | 政策库列表滚动，然后点开一条，右侧抽屉弹出原文与抽取结果 | 每一份文件都被拆成工具、渠道、目标；每一条判断都能点回原句 |
| 4 | 40—60s | 切到央地传导页，镜头推近时滞排行条形图 | 中央发文之后，这六个地方隔了多久才动？中位数十六天，最慢七十七天 |
| 5 | 60—75s | 切到散点图（图 4），停留 | 但真正的差异不在快慢，在看得见多少——北京公开两百多份，观察到五组；有的地方只公开十份 |
| 6 | 75—88s | 报告页面，滚动展示 8 页 | 这些结论被写成一份完整报告，可打印、可直接分发 |
| 7 | 88—90s | 收尾：标题 + 访问地址 | 经纬纵横 |

### 4.3 制作要求

- **分辨率**：1920×1080，30fps
- **录屏素材**：用 `docs/screenshots/` 的静态图做「推拉摇移」（Ken Burns），不要用假造的动态 UI 动画——截图里没有的交互，不要凭空生成
- **字幕**：全程中文字幕（`.srt` 一并交付），字号够大，深底白字
- **配乐**：可有可无。若有，音量压到 -24dB 以下，不能盖过人声；用无版权音源
- **旁白**：可用 TTS，但要选沉稳的男/女声，不要选「抖音解说腔」。语速约每秒 4—5 字
- ⚠️ **不要用 AI 生成的政策场景视频素材**（会议室、文件、握手之类的空镜）。这个项目的气质是「证据」，插空镜会变成宣传片

## 5. 任务 C：平台视觉升级

### 5.1 先说清楚这件事的边界

你要交付的是**设计规范 + 视觉稿**，不是改完的代码。原因有两个：

1. 你看不到运行效果，盲改 CSS 会崩（这个项目有 8 个页面、约 40 个 CSS 文件，改一个 token 会牵动全站）
2. 你没有仓库写权限，改了也推不上来

所以交付物是：

| 交付 | 形式 | 说明 |
|---|---|---|
| C1 视觉诊断 | Markdown | 逐页指出问题，附截图标注 |
| C2 设计规范 v2 | Markdown 表格 | 色彩 / 字体 / 间距 / 圆角 / 阴影 / 动效，**沿用现有变量名** |
| C3 tokens 补丁 | `.css` 片段 | 只写 `:root` 里的变量覆盖，不写选择器 |
| C4 三张视觉稿 | PNG 1440×900 | 政策扫描、央地传导、研究报告三页的高保真稿 |

### 5.2 现有视觉体系（必须在这个体系里升级，不是重做）

```css
/* 基底：深空墨黑，带一点青，避免纯黑发死 */
--paper:    #070c0e;   --paper-2: #0b1215;
--paper-3:  #0f181c;   --paper-4: #132026;

/* 文字：不用纯白，带青的浅灰，长时间看不刺眼 */
--ink:      #e7f1ed;   --ink-soft: #b3c6c0;
--muted:    #7f948e;   --muted-2:  #5d726c;

/* 分隔线：低透明度青绿，形成"仪表刻度"感 */
--line:        rgba(120, 214, 190, 0.14);
--line-strong: rgba(120, 214, 190, 0.30);

/* 主强调：信号青绿 */
--green: #2ee6b2;  --green-2: #7bffd8;  --green-3: rgba(46,230,178,0.10);

/* 语义色 */
--rust: #ff8f6b;  --amber: #ffc247;  --blue: #7fb2ff;  --violet: #b9a5ff;

/* 字体：三套分工明确 */
--serif: "Noto Serif SC", ...        /* 标题，权威感 */
--sans:  "Inter", "Noto Sans SC" ... /* 正文 */
--mono:  "IBM Plex Mono", ...        /* 数字、日期、代码 */
```

**这个体系里有四件事是项目的识别度，不许动：**

1. **深色底**。全站深色是「情报终端」的核心气质，改成浅色就变成普通看板。
2. **青绿是唯一主强调色**。橙（rust）、黄（amber）只用于状态语义，不能拿来当装饰色。
3. **数字必须等宽**。图表里所有天数、日期靠 `--mono` 对齐，换成非等宽字体，整个矩阵会错位。
4. **衬线标题 + 无衬线正文的对比**。这是它不像「AI 生成模板」的关键。

### 5.3 可以动的部分（这些是真问题）

| 问题 | 现状 | 期望 |
|---|---|---|
| 色彩层次偏平 | 深底上四层纸色差很小（#070c0e → #132026），卡片叠卡片时分不清层级 | 拉开卡片层的明度差，或引入极淡的描边 + 内阴影区分层级 |
| 强调色过饱和 | `#2ee6b2` 在大面积填充时刺眼 | 大面积用降饱和变体，保留原色给文字与小面积 |
| 状态色语义不统一 | 跟进用绿、先行用蓝、零命中用灰，但「先行」在同一张图里和「跟进」区分度不够 | 建立一张状态色卡（6 种状态一一对应），全站统一 |
| 数据密度高时呼吸感不足 | 18×6 矩阵、7 列表格在小屏上挤 | 给出密度分级规范（舒适 / 紧凑两档） |
| 缺少"数据即视觉"的记忆点 | 目前视觉靠布局撑，没有品牌级元素 | 提出一个可复用的视觉母题（例如「刻度 / 扫描线 / 网格」的克制使用），★可选，不建议大幅改动 |

### 5.4 三张视觉稿的具体要求

任选其一作为主改，其余两页保持一致性：

1. **政策扫描**（首屏，决定了第一印象）—— 现在是左文右环图。可探索：把「7/7 源在线」做成更明确的系统状态条
2. **央地传导**（信息量最大的页）—— 矩阵 + 条形图 + 省份卡三块并存。可探索：重排信息优先级，让「中位 16 天」更早被看到
3. **研究报告**（对外交付物）—— 这页是浅底 A4 文档预览，与全站深色形成对比。要注意：**报告本身是白底印刷品，不要为了统一而改成深色**，印刷和屏幕是两套介质

### 5.5 视觉稿的技术要求

- 尺寸 1440×900，PNG，2 倍图（2880×1800 也接受）
- 必须用**真实文案与真实数字**，不要 Lorem ipsum、不要「示例数据 123」
- 中文字体渲染要正确（不要出现方块、不要用系统默认宋体凑）
- 每张图配一段 100 字以内的说明：改了什么、为什么、预期效果

## 7. 三条红线

### 红线一：不许编数字
第 2 节之外任何数字都要先问。默认不用。

### 红线二：不许把「边界」删掉
P10、P13 这两页（全国能说到什么程度、局限）**不许为了版面好看删掉或缩小**。这个项目最值钱的就是它敢说自己不知道。删掉这两页，它就变成又一个「看起来很厉害」的作业。

### 红线三：不许改掉深色终端风
可以调明度、可以加层次、可以换字体权重，但不许改成浅色、不许新增彩色渐变背景、不许引入玻璃拟态（glassmorphism）。

## 8. 交付与验收

### 8.1 交付顺序

按 A → B → C 做，**每完成一件先回传，不要三件一起打包**。理由：A 的错误（比如数字用错）会原样传染到 B 和 C，越早发现越省事。

### 8.2 验收标准（可验证）

| 任务 | 通过条件 |
|---|---|
| A · PPT | ① 14 页 ±2；② 第 2 节所有引用数字与 PPT 一致（逐条核对）；③ P9 图上无拟合线；④ P10、P13 存在；⑤ 打开无字体缺失、无文字溢出边界 |
| B · 视频 | ① 时长 90s ±5s；② 有 `.srt` 字幕且时间轴对齐；③ 无 AI 生成空镜；④ 旁白语速不赶；⑤ 画面无糊、无拉伸变形 |
| C · 视觉 | ① 四件交付齐全；② tokens 补丁只覆盖 `:root`；③ 三张视觉稿用真实数据；④ 说明里写清「为什么改」而不是只写「改了什么」 |

### 8.3 遇到拿不准的

拿不准就**先写进 `04_note` 的问题清单**，不要自己决定。典型场景：

- 某个数字在两个文档里不一致 → 记下来，用 `docs/01_项目书.md` 的版本
- 某页 PPT 塞不下 → 拆页，不要缩字号
- 视觉稿和现有体系冲突 → 出两版，标注 A/B 让作者选
