### 状态分布自检

108 个组合的完整分布：`respond 7 + pre 8 + none 89 + uncovered 36 + outside 1 = 141`。

> 141 而不是 108，是因为 `uncovered` 计入了未通过闸门的 2 个省份（山西、江苏）× 18 个主题 = 36 格。扣除后 141 − 36 = 105，而实际可观察是 107。差 2 格的原因：`totalPairs` 只按 **6 个可用省份** 计算（6×18=108），而 `uncovered` 那 36 格来自另外 2 个省份。**这不是 bug，是统计口径的差异**，但看状态分布时容易看晕，特此记录。

### 一个数据契约不一致（已记录）

`data/locals.json` 磁盘上没有 `ready` 字段，`ready:true` 是 `server/index.mjs` 在响应时补的。所以直接用磁盘文件调 `buildTransfer` 会返回 `null`（因为 `payload.ready` 未通过）。复验脚本里显式补了 `{...locals, ready:true}`。

**接手时注意**：读磁盘和读接口拿到的结构不完全一样。

## 四、视觉验证

### 4.1 时滞排行与刻度的对齐（像素测量）

问题：截图看不出亚像素误差，必须量数字。在 iframe 里读取 DOM 实际位置：

```
scale0=396.0  scale90=1150.0  trackLeft=396.0  trackW=754.0  barRight=1041.2  pct=85.6
```

判读：
- 刻度 0 的位置（396.0）= 条形轨道左边界（396.0）✅ 共用同一起点
- 刻度跨度 1150.0 − 396.0 = 754.0 = 轨道宽度 754.0 ✅ 共用同一尺度
- 最长条（+77 天）末端在 85.6% 处，77÷90 = 85.56% ✅ 误差 0.04%

### 4.2 本轮修掉的两个视觉缺陷

**缺陷 V1：导出图与网页用了不同的刻度上限**

- 现象：同一根 77 天的条，网页上接近右端，导出图里只到 2/3 处。
- 原因：`exportImage.ts` 用 `max × 1.08 = 83.16` 作上限，网页用 `ceil(77/30) × 30 = 90`。
- 修复：导出统一改为 `Math.max(30, Math.ceil(peak / 30) * 30)`。
- 复验：修复后导出图 60 刻度在 831px、条末端在 981px，77÷90 比例成立。

**缺陷 V2：图例压住刻度「0」**

- 现象：白底导出图顶部，图例"60 天以上"与刻度"0"叠在一起。
- 原因：图例从 `PAD=52` 起排，总宽约 380px，而刻度起点 `trackX = PAD + LABEL_W = 302`。**必然重叠。**
- 修复：图例改为右对齐到 `W - PAD`，放在标题行同一水平线上。
- 复验：修复后图例右端距画布右边 52px，与刻度区完全分离。

**另外一并修掉的**：中位虚线原本画在条形之上，会横穿右侧的天数标签（+14 天、+16 天）。改为先画线、后画条、最后画字，让条形自然遮住线条。
