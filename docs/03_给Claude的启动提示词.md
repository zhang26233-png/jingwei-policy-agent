# 给 Claude 的启动提示词

> 用法：把下面「第一段」整段复制给 Claude（配合仓库链接或上传的代码包）。
> 如果它一次读不完整个仓库，用后面的「分片方案」。
> **第一轮不要让它写代码。** 先让它确认路线、列缺陷、给交付清单，人确认后再动手——这一条能省掉大量返工。

## 第一段：可直接复制

```
我在接手一个已经上线、但需要继续开发的项目。仓库：https://github.com/zhang26233-png/jingwei-policy-agent

先不要写任何代码。第一轮只做三件事：① 复述你理解的项目与当前状态；② 列出你从代码和文档里发现的问题（分严重度）；③ 给出你建议的下一步交付清单（分优先级，每项写验收判据）。等我确认后再动手。

项目是什么：
一个中国宏观经济政策的证据分析系统。它从 7 个中央部委官网和 8 个地方政府门户自动抓取政策文件，做结构化抽取，然后计算政策优先级、传导机制链、政策间关系、省级影响，以及「央地传导」——比对中央发文日与地方跟进日的时间差。前端 React 19 + TypeScript + Vite，后端 Node 原生 http，单端口 8787 同时提供页面和 API。

先读这五个文件，按顺序：
1. docs/01_项目书.md —— 这东西是什么、研究问题、已有结论、诚实的边界
2. docs/02_移交书.md —— 架构、代码地图、数据契约、已知缺陷 D1—D9
3. docs/04_任务清单与后续规划.md —— 已经排好的优先级
4. src/lib/transfer.ts —— 央地传导的全部判定逻辑
5. server/locals.mjs —— 地方语料采集

三条红线，任何改动都不能违反：
1. 抓不到就留空，不许编。8 个地方源只有 6 个能过门槛，另 2 个必须显示「未纳入」并写明原因，不许改阈值让它们通过，不许用邻近省份推断填补。
2. 数值结论必须可复算。页面上每个分数、排名、天数都要能由 src/lib 下的纯函数从原始数据算出，能定位到具体规则。不要让模型参与数值判断。
3. 边界要写在页面上，不是写在文档里。覆盖率、观测窗、样本量这些限制必须出现在用户能看到的界面里，文档里写了但页面上没写等于没写。

最容易被破坏的地方（已知会改错）：
- 央地判定有六种状态：respond / pre / likely / none / outside / uncovered。none 和 outside 绝不能合并——合并就是拿栏目边界当政策事实。pre 不能并进时滞统计，否则中位数被系统性压短。
- 省份「省级/市级」的判断必须用 startsWith('省级')。广州的 level 是「市级（副省级省会）」，用 includes('省级') 会把它误判成省级。
- server/extract.mjs 的 DOC_RULES 顺序敏感，policy 规则和在前的「工作动态」规则不能互换。
- 主题锚点是 18 个领域锚点，不要改回「专项工具」路线——早期 8 个专项工具在 617 份地方文件里几乎全零命中。
- 导出图（src/lib/exportImage.ts，canvas 手绘）与网页（transfer.css）是两套渲染，分档色和刻度上限必须同步。

当前最急的问题（如果你同意，这是第一优先）：
D1 —— data/locals.json 是 2026-11-07 的静态快照，服务不会自动更新。而且 GATE.minLatest 是硬编码日期 '2026-10-20'，三周后所有省份都会被判成「停更」，央地传导页会空掉。建议改成相对于 payload.at 的偏移，并给采集加定时或按需触发。

请先告诉我：
1. 你是否认同 D1 是第一优先？如果不同意，你认为什么更急？
2. docs/02_移交书.md 第 8 节列了 D1—D9，你觉得有没有漏掉的缺陷？
3. 如果你只能做一件事，你会做哪件？
```

## 第三段：约束它的常见误判

如果 Claude 出现下面这些倾向，直接把对应的一段贴给它。

**当它想加页面时：**

```
不要再增加页面。项目已有 9 个页面，功能过剩。当前缺的是证据密度和可交付性，不是功能数量。
如果你认为需要新页面，先说清楚它解决的是哪个现有页面解决不了的问题。
```

**当它想扩省份时：**

```
扩省份是死路。31 个省级门户实测只有 5 个能稳定抓到政策文件列表，其余是 403/412 拒绝、JS 渲染、或栏目已停更。
这条结论本身就是研究结论的一部分，不要反复试探。
```

**当它想用「全国差异」这个词时：**

```
样本是 6 个地方单元、7 组跟进。这个量级撑不起「全国差异」，只能做「多案例比较」。
用「全国」这个词，评委问一句「7 个点怎么算差异」就崩了。
```

**当它想引入模型做数值判断时：**

```
模型不参与数值判断。它的职责是把已经算好的规则结果写成可读段落。
一旦让模型产生分数，这个项目就变成了它自己批评的「套壳大模型」，全部可复算性都失效。
```

**当它想重构时：**

```
接受小步改造，不接受整体重写。当前代码是能跑、能上线、有真实数据的状态。
重写会丢弃所有口径修正的上下文——那些修正每一条都是拿真实误判换来的，注释里写着原因。
```
