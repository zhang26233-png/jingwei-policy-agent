面向科研人员、政策制定者参考与公众理解的政策证据工作台。

四个能力：**多源自动检索中央政策 → 结构化汇总整合 → 规则化评估分析 → 省级影响可视化**。所有结论都能回到原文、来源等级与计算口径，系统会主动展示语料边界与不确定区间。

**首页是一键研判：不需要输入问题。** 按一次「启动扫描」，系统自动完成七步流水线——连接官方栏目 → 抓取近期政策原文 → 结构化抽取 → 七维度优先级排序 → 传导机制建模 → 政策关系推演 → 省级影响计算——直接产出四份结果：优先级榜、作用机制链、相互关系图、省级影响排名。

> 语料来自中国政府网、财政部、国家发展改革委、中国人民银行、国家统计局的公开页面，**自动采集**，不是手写样例。除 8 条人工校订语料作兜底外，其余条目均由采集服务抓取并结构化。

## 运行

要求：Node.js 20+（本机已验证 Node 22）。

**一条命令启动（推荐，单端口同时提供网页与 API）：**

```bash
cd macro-policy-agent
npm install
npm start
```

打开 `http://127.0.0.1:8787/`。

**开发模式（前端热更新 + 代理后端）：**

```bash
npm run server     # 终端 1：采集与语料服务，端口 8787
npm run dev        # 终端 2：前端，端口 5173
```

打开 `http://127.0.0.1:5173/`。

## 一键研判的四个结果

1. **优先级排序**：发文层级 22%、时效性 18%、力度强度 18%、覆盖广度 13%、约束强度 12%、政策信号 12%、新增信息 5%，加权后分 S／A／B／C。每条都给出分数最高的三项理由与需注意的短板。
2. **作用机制与影响逻辑**：每条重点政策最多两条传导链，固定四段——政策工具 → 中间变量 → 主体行为 → 宏观结果，并标注方向（扩张／收紧／未定）、强度（1—3 格）、时滞、原文依据句和失效条件。
3. **相互关系图**：环形网络，五类关系——配套协同、时序承接、工具互补、目标张力、主题重叠；给出组合合力方向（偏扩张／偏收紧／结构性混合），并说明哪几条线在发力、哪条渠道本期缺席。
4. **省级影响**：34 个省级单位的暴露度、受益与承压拆解，可跳到完整地图。

> 关系推导依据同发文机关、同主渠道、时间距离与方向异同，属于**推断**，不等于发文机关确认的配套关系。

### 可用性判据：看"近 90 天还在不在更新"，不数历史存量

早期版本用的是"条目数 ≥30 且跨度 ≥60 天"，结果把黑龙江（35 条、近 90 天仅 4 份）、辽宁（20 条、近 90 天 2 份）算成可用，把陕西（14 条、近 90 天 8 份）排除在外——判反了。

现行判据：

- 近 90 天的政策工具类条目 ≥ 6 份；
- 栏目最新条目晚于 2026-10-20（否则 10 月下旬的中央政策观察不到）。

### 观测窗：窗口外的格子不做判断

每地栏目回溯深度不同（北京到 5 月，陕西到 6 月）。中央发文日落在窗口外时，格子标 **"超出窗口"**，既不算跟进也不算未见。这一条很关键——不加的话，"上海 9 月才有数据"会被读成"上海没跟进 9 月的政策"。

### 四种判定不能混用

- **已跟进**：标题命中主题词 + 是政策工具（通知/意见/方案/办法/规划…）+ 未含事务性排除词，且日期晚于中央发文 → 计入时滞。
- **早于中央**：标题命中但日期早于中央发文 → 多为地方先行试点，应解释为"中央吸收了地方做法"。
- **疑似承接**：标题没写，但正文里同一主题出现 ≥5 次且晚于中央发文 → 标注"待核"，**不计入**时滞。
- **超出窗口**：中央发文日不在该地栏目的观测窗内 → 不判断。

### 事务性文件必须排除

真实命中里混进过"人工智能领域颠覆性技术方向储备**课题征集**""文物保护工程**资质单位培训班**""仲裁委人员**解聘**通知"——它们都以"通知"结尾，都会让时滞瞬间归零。`EXCLUDE_DOC` 词表（培训/征集/课题/名录/解聘/公示/资质/批复…）就是拿这些真实误判逐条打出来的补丁。

### 本期实测结论（2026-11-07 数据）

18 个主题锚点、6 个地方单元、107 个可观察组合：

- 观察到 **7 组**"中央发文—地方跟进"，覆盖 6 项政策，中位时滞 **16 天**；
- 最快：北京·住房公积金 +6 天；最慢：河北·电力 +77 天；
- 8 组地方文件早于中央（上海占 5 组）——这些领域中央更像在追认地方已有做法；
- **北京一家占 5/7 组跟进**，但它的栏目同时收委办局和区级文件（近 90 天 215 份，其他地方个位数到几十份）。跨地区比时滞，比的其实是各栏目的文件公开密度，不是行政效率。这条必须写进结论，否则会把收录差异读成执行力差异。

### 已知限制

- 是**主题级配对**，不是逐份文件配对——中央与地方文件之间没有官方对应编号。
- 栏目口径不一致：北京、上海收委办局与区级文件，广东、河北只收省政府及办公厅文件。
- 只统计"最早一份"，回答"什么时候开始动"，不评价后续力度与配套强度。
- 样本是便利样本：京津冀 2、长三角 1、珠三角 2、西部 1，东北与中部大部缺席。
- 18 个主题是按领域设的锚点，不是中央文件的穷举——63 份政策文件里选了地方有对应事权的 18 项。

### 实测抓不到、因此没有接入

写出来是为了避免一个常见误判：**把"没抓到"当成"没有政策"**。

|---|---|
| 工业和信息化部 | 栏目页只返回空壳，列表由前端脚本渲染 |

### 采集流程：两阶段

1. **列表阶段**（并发 5 路）：各源取列表，按时间窗过滤，跨源按 URL 归一化去重。
2. **正文阶段**（并发 5 路，带配额）：政策原文优先、新的优先，同时**强制给背景材料留 20% 配额**——否则政策原文一多，新闻与统计数据会被整体挤掉，影响页就没有观测背景。

抓完 → 结构化抽取 → 入库去重 → 记录本次运行。数据落地 `data/policies.json`。

### 附件解析：正文不在网页上怎么办

政府文件的实体内容经常只放在附件 PDF 里，网页上只剩一纸「现将《XX 规划》印发给你们」。这类页面正文往往不到 800 字，直接抽取等于什么都没抽到。

所以正文阶段加了一层判定：**网页正文短于 900 字时，回同页找附件**。

- 只并「与文件同名」的 PDF 正文（标题包含附件名，或页面只有一个 PDF 附件），并入后才做结构化抽取；
- **清单、名单、表格型附件只登记不并入**——表格拉平成文本是一堆短碎片，混进正文会把渠道关键词密度与量化目标算歪；
- 扫描件（无文字层）、OFD、DOC、超过 12MB 的文件如实标记「未并入」并写明原因，不假装解析成功；
- 每份附件的角色（正文／清单／其他格式）、页数、字数、失败原因都写进政策记录，详情面板与体检页可直接查看。

当前语料 57 条政策文件里：

| 状态 | 条数 | 说明 |
|---|---|---|
| 正文来自 PDF 附件 | 5 | 共补入 40,400 字，含 4 份「十五五」规划全文 |
| 附件未并入正文 | 3 | 1 个 DOC、1 个 61MB 超限、1 个表格型 |
| 只挂清单类附件 | 2 | 正文本身完整，附表不计入 |
| 页面无附件 | 47 | 正文直接在网页上 |

**文档类型分开处理**：`政策文件 / 发布实录 / 数据发布 / 工作动态`。政策库默认只把"政策文件"当作政策；省级推演也只用政策文件，避免把新闻发布会或监管局动态当成政策工具。

## 一条政策被拆成两层

抽取是规则引擎，只认字面能核对的模式，抽不到就留空，不做语义补全。

**第一层 · 用于排序与计算**

发文机关、文号、日期、文种、主题、政策工具、作用对象、政策目标、九条传导渠道的命中密度、金额与比例数字。这一层决定优先级分数、机制链与省级影响。

**第二层 · 用于逐条阅读（点任一政策打开详情面板）**

| 区块 | 内容 | 抽取方式 |
|---|---|---|
| 文件结构 | 一、二、三……章节骨架 | 匹配原文编号行，不改写标题 |
| 原文要点 | 可作为证据的句子 | 按含数字与政策动词的密度筛选 |
| 条款分类 | 目标／约束／禁止／激励／程序 | 按语气与动词归位，同一句只归一类 |
| 量化指标 | 金额、比率、到某年的量化目标 | 金额按亿元／万元分开计量，不做口径换算 |
| 落实安排 | 实施主体、资金来源、时间节点、适用范围 | 只认"由 X 负责""所需资金由…承担""自…起"等明确表述 |
| 传导渠道 | 各渠道命中次数 | 正文关键词密度，条形按相对最大值绘制 |
| 原文分段 | 清理导航串后的正文段落 | 保留段落结构，可展开全文 |

**附件的处理**：正文在 PDF 里的，已在采集阶段解析并入（见上文「附件解析」）。仍有三类读不出来，界面会逐条写明原因：DOC 二进制、OFD 国标版式、超过 12MB 的大部头文件（例如 61MB 的《政府收支分类科目》）。这三类不进入字段统计，也不会被算成「抽取漏抽」。

## 省级影响模型怎么算

1. **政策 → 渠道**：每份政策按正文关键词密度得到 9 条传导渠道的权重（财政投资、转移支付、信贷成本、居民消费、房地产、外贸、民营、就业民生、产业升级）。
2. **政策方向**：按措辞与税种判断扩张 / 收紧 / 方向不明。方向不明的渠道保留展示，但**不计入省级打分**。
3. **省份敏感度**：每个省份用结构标签（制造业占比、外向型、民营活跃、财政转移支付依赖、资源型等）映射到渠道系数，再在渠道内跨省归一化，避免大省恒高。
4. **得分**：`渠道权重 × 省份敏感度 × 方向`，汇总成受益侧、承压侧、暴露度；面板里的渠道拆解相加严格等于受益 / 承压。

⚠️ 这是**结构推演**，不是计量估计：不含地方细则、转移支付分配公式与项目落地进度，因此只能比较"受影响程度"，不能比较"受益金额"。

## 协同测度：一致性 PCI 与可执行性 PEI

老师提的"政策协同"，落到能算、能复算的地方只有两件事：**政策之间方向对不对得上**，**这些政策有没有被执行的条件**。前者是 PCI，后者是 PEI，两个指数交叉成四象限。

**PCI（政策一致性，0—100）**，三项加权，原料全部来自已抽取字段：

| 分项 | 权重 | 算法 |
|---|---|---|
| 横向一致 | 45% | 同一渠道内，方向赋 ±1、按渠道权重求和后取绝对值，除以权重和：`|Σwᵢpᵢ| / Σwᵢ` |
| 时序一致 | 30% | 同渠道内方向翻转次数 ÷ 该渠道政策数，翻转越多扣得越多 |
| 目标—工具 | 25% | 从量化目标与目标类条款识别"文件说要发力的渠道"，检查本渠道上有没有对应工具 |

**PEI（政策可执行性，0—100）**，五项各 20 分：目标可测、责任可归属、资源有保障、时限明确、可考核。每项只在文本写明时才给分，抽不到就记 0 并在面板上写出缺的是什么。

⚠️ **PEI 测的是"文本完备度"，不是"实施效果"。** 政策有没有真的起作用，要接统计指标做目标—实绩偏差，那是另一个工程；把文本分数说成效果，是最容易被追问倒的一步。

**四象限的分界线取本期九条渠道的中位数**（不是拍一个 55 分）：本期一致性中位数 66、可执行性中位数 45。换一条线会改变个别渠道的归属，所以分界线在页面上直接写出来。

**方向并存只并列、不断言**：同渠道内扩张与收紧同时出现时，页面并列两组文件，但不写"甲与乙冲突"——仅凭方向词无法判断两份文件是否针对同一对象。要写成实质冲突，必须回原文比对。

**编码信度**：方向由关键词规则判定，属人工可复核的编码。页面按渠道分层抽 30 条，可导出 CSV 填人工判定列，算出编码一致率——论文的方法学部分需要这个数字。

## 已知边界

- 只覆盖中央层面政策，不含地方实施细则与执行进度
- 省份敏感系数是定性归纳，尚未用统计年鉴或投入产出表校准
- 不进行因果识别，不输出"政策使某指标变化多少"的精确结论
- 抽取是关键词密度规则，个别文件会出现工具名不准确，界面提供原文入口供人工复核
- 附件解析只覆盖 PDF 正文：DOC／OFD／超过 12MB 的文件，以及扫描件（无文字层），会标注未并入的具体原因，不做 OCR
- 七个来源之外，工信部、商务部、住建部、人社部、金融监管总局因前端渲染或改版无法直连，需人工补录
- 地图为分析示意图，行政边界来自公开省级矢量数据（含台湾省、香港、澳门与南海诸岛插图），不作为国界与行政区划的权威依据
- 协同指数测的是文本完备度与方向一致性，不含实施效果；方向与渠道归属均为关键词规则，须以抽检一致率说明可靠性
- 当前没有调用大模型；正式版的大模型只做字段抽取与表达，结论仍由数据库与证据校验生成
