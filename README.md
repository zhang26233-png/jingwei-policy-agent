# 宏策智研 · 中国宏观经济政策证据分析智能体（校赛 MVP）

面向科研人员、政策制定者参考与公众理解的政策证据工作台。

四个能力：**多源自动检索中央政策 → 结构化汇总整合 → 规则化评估分析 → 省级影响可视化**。所有结论都能回到原文、来源等级与计算口径，系统会主动展示语料边界与不确定区间。

**首页是一键研判：不需要输入问题。** 按一次「启动扫描」，系统自动完成七步流水线——连接官方栏目 → 抓取近期政策原文 → 结构化抽取 → 七维度优先级排序 → 传导机制建模 → 政策关系推演 → 省级影响计算——直接产出四份结果：优先级榜、作用机制链、相互关系图、省级影响排名。

> 语料来自中国政府网、财政部、国家发展改革委、中国人民银行、国家统计局的公开页面，**自动采集**，不是手写样例。除 8 条人工校订语料作兜底外，其余条目均由采集服务抓取并结构化。

## 运行

要求：Node.js 20+（本机已验证 Node 22）。

**一条命令启动（推荐，单端口同时提供网页与 API）：**

```bash
cd macro-policy-agent
npm install
npm start
```

打开 `http://127.0.0.1:8787/`。

**开发模式（前端热更新 + 代理后端）：**

```bash
npm run server     # 终端 1：采集与语料服务，端口 8787
npm run dev        # 终端 2：前端，端口 5173
```

打开 `http://127.0.0.1:5173/`。

## 一键研判的四个结果

1. **优先级排序**：发文层级 22%、时效性 18%、力度强度 18%、覆盖广度 13%、约束强度 12%、政策信号 12%、新增信息 5%，加权后分 S／A／B／C。每条都给出分数最高的三项理由与需注意的短板。
2. **作用机制与影响逻辑**：每条重点政策最多两条传导链，固定四段——政策工具 → 中间变量 → 主体行为 → 宏观结果，并标注方向（扩张／收紧／未定）、强度（1—3 格）、时滞、原文依据句和失效条件。
3. **相互关系图**：环形网络，五类关系——配套协同、时序承接、工具互补、目标张力、主题重叠；给出组合合力方向（偏扩张／偏收紧／结构性混合），并说明哪几条线在发力、哪条渠道本期缺席。
4. **省级影响**：34 个省级单位的暴露度、受益与承压拆解，可跳到完整地图。

> 关系推导依据同发文机关、同主渠道、时间距离与方向异同，属于**推断**，不等于发文机关确认的配套关系。

### 实测抓不到、因此没有接入

写出来是为了避免一个常见误判：**把"没抓到"当成"没有政策"**。

| 来源 | 失败原因 |
|---|---|
| 工业和信息化部 | 栏目页只返回空壳，列表由前端脚本渲染 |
| 商务部 | 栏目路径已改版，原公开目录 404 |
| 住房城乡建设部 / 人力资源社会保障部 | 栏目页返回空页面或极短占位页 |
| 国家金融监督管理总局 | 列表动态加载，无公开结构化接口 |

复检命令：`node server/probe-sources.mjs`，会逐个打印可达性、锚点数、可识别条目数。

### 采集流程：两阶段

1. **列表阶段**（并发 5 路）：各源取列表，按时间窗过滤，跨源按 URL 归一化去重。
2. **正文阶段**（并发 5 路，带配额）：政策原文优先、新的优先，同时**强制给背景材料留 20% 配额**——否则政策原文一多，新闻与统计数据会被整体挤掉，影响页就没有观测背景。

抓完 → 结构化抽取 → 入库去重 → 记录本次运行。数据落地 `data/policies.json`。

**文档类型分开处理**：`政策文件 / 发布实录 / 数据发布 / 工作动态`。政策库默认只把"政策文件"当作政策；省级推演也只用政策文件，避免把新闻发布会或监管局动态当成政策工具。

## 一条政策被拆成两层

抽取是规则引擎，只认字面能核对的模式，抽不到就留空，不做语义补全。

**第一层 · 用于排序与计算**

发文机关、文号、日期、文种、主题、政策工具、作用对象、政策目标、九条传导渠道的命中密度、金额与比例数字。这一层决定优先级分数、机制链与省级影响。

**第二层 · 用于逐条阅读（点任一政策打开详情面板）**

| 区块 | 内容 | 抽取方式 |
|---|---|---|
| 文件结构 | 一、二、三……章节骨架 | 匹配原文编号行，不改写标题 |
| 原文要点 | 可作为证据的句子 | 按含数字与政策动词的密度筛选 |
| 条款分类 | 目标／约束／禁止／激励／程序 | 按语气与动词归位，同一句只归一类 |
| 量化指标 | 金额、比率、到某年的量化目标 | 金额按亿元／万元分开计量，不做口径换算 |
| 落实安排 | 实施主体、资金来源、时间节点、适用范围 | 只认"由 X 负责""所需资金由…承担""自…起"等明确表述 |
| 传导渠道 | 各渠道命中次数 | 正文关键词密度，条形按相对最大值绘制 |
| 原文分段 | 清理导航串后的正文段落 | 保留段落结构，可展开全文 |

**已知缺口**：政府文件的核心内容常常只放在附件（PDF／OFD）里，网页正文只有一纸通知。系统能识别这类情况并标注"主体在附件"，但**不解析附件内容**。当前语料中约六分之一属于这种情况。

## 省级影响模型怎么算

1. **政策 → 渠道**：每份政策按正文关键词密度得到 9 条传导渠道的权重（财政投资、转移支付、信贷成本、居民消费、房地产、外贸、民营、就业民生、产业升级）。
2. **政策方向**：按措辞与税种判断扩张 / 收紧 / 方向不明。方向不明的渠道保留展示，但**不计入省级打分**。
3. **省份敏感度**：每个省份用结构标签（制造业占比、外向型、民营活跃、财政转移支付依赖、资源型等）映射到渠道系数，再在渠道内跨省归一化，避免大省恒高。
4. **得分**：`渠道权重 × 省份敏感度 × 方向`，汇总成受益侧、承压侧、暴露度；面板里的渠道拆解相加严格等于受益 / 承压。

⚠️ 这是**结构推演**，不是计量估计：不含地方细则、转移支付分配公式与项目落地进度，因此只能比较"受影响程度"，不能比较"受益金额"。

## 已知边界

- 只覆盖中央层面政策，不含地方实施细则与执行进度
- 省份敏感系数是定性归纳，尚未用统计年鉴或投入产出表校准
- 不进行因果识别，不输出"政策使某指标变化多少"的精确结论
- 抽取是关键词密度规则，个别文件会出现工具名不准确，界面提供原文入口供人工复核
- 附件（PDF／OFD）不解析，正文只有通知的文件已标注"主体在附件"
- 七个来源之外，工信部、商务部、住建部、人社部、金融监管总局因前端渲染或改版无法直连，需人工补录
- 地图为分析示意图，行政边界来自公开省级矢量数据（含台湾省、香港、澳门与南海诸岛插图），不作为国界与行政区划的权威依据
- 当前没有调用大模型；正式版的大模型只做字段抽取与表达，结论仍由数据库与证据校验生成
